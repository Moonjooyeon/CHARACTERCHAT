# KG이니시스 연결 상태

KG 웹표준 PC 카드 결제 어댑터를 추가했습니다. 기본 비활성 상태입니다. 실제 KG 인증·승인 또는 운영 배포를 수행하지 않았습니다. 모바일 결제와 일반 취소·환불 API는 아직 구현하지 않았으므로 전체 운영 준비 완료 상태가 아닙니다.

공식 명세: https://manual.inicis.com/pay/stdpay_pc.html

## 서버 설정

다음 값은 서버 환경에만 설정합니다. Sign Key를 채팅, 저장소, 클라이언트 환경변수에 넣지 마세요.

- `KG_ENABLED`: 연결을 검증한 환경에서만 `true`
- `KG_PAYMENT_MODE`: `test` 또는 `live`
- `KG_MID`: 가맹점 MID. 테스트 모드는 `INIpayTest`만 허용
- `KG_SIGN_KEY`: 해당 MID의 웹결제 Sign Key (서버 secret)
- `PAYMENT_ORIGIN`: 결제창을 여는 HTTPS origin. 후행 슬래시 없음
- `KG_PACKS_JSON`: 서버 승인 판매상품 배열. 각 항목 `{id,name,units,price}`. price는 원 단위 양의 정수. 임의 운영 가격을 넣지 않았음
- `KG_LIVE_CONFIRMED`: 운영 계약·판매상품·환불 절차·실환경 검증 완료 후 운영 전환 시 `true`

`0013_cloudy_zemo.sql`을 대상 D1에 적용해야 합니다. 생성된 Drizzle schema와 metadata도 포함됩니다. 이번 작업에서는 운영 DB를 변경하지 않았습니다.

## 동작

로그인한 사용자만 주문 생성/조회 가능. 가격과 지급량은 서버 상품에서 확정. 구매자 이름·전화·이메일은 결제 요청에만 사용하고 주문 테이블에는 저장하지 않습니다. 콜백 token, MID, 주문번호, IDC와 승인 URL을 검증합니다. 서버 승인 결과의 MID·MOID·금액·거래번호를 검증하고 주문 완료와 ledger 지급을 D1 batch로 처리합니다. 테스트 승인은 유료 잉크를 지급하지 않습니다.

승인 네트워크 오류 또는 결과 불일치는 망취소를 요청합니다. 망취소 실패는 `review`로 남습니다. 프로세스 강제 종료로 `processing`이 남을 수도 있습니다. 운영자는 이 주문을 KG 관리자 거래조회와 대조하고 해결해야 하며 재청구하면 안 됩니다. 자동 정산 복구 작업은 미구현입니다. 망취소는 일반 환불 용도가 아닙니다.

현재 localhost:8080은 정적 목업이라 실제 PG/API를 호출하지 않습니다. 실연동은 서버 앱과 공개 HTTPS 반환 주소에서 검증해야 합니다.

## 검증

`node scripts/verify-kg.cjs`: 외부 요청 없는 모의 D1/승인 테스트. 비활성 차단, Origin 검증, 서버 가격, 서명, 동일 주문 복구, 소유권, URL/IDC 검증, 중복 지급 방지, 불일치 망취소 검증.

남은 필수 입력: KG 상품 종류 확정(이니시스 여부), 가맹점 MID/키 발급 여부, 실제 상품 가격, 운영 HTTPS 주소. 모바일/환불/정산 복구와 실제 PG 샌드박스 검증 후 운영을 활성화해야 합니다.
